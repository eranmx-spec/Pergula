# עץ וצל — דף נחיתה

דף נחיתה לפרגולות, דקים, מעקות עץ וגדרות. כל פנייה מהטופס נכתבת כשורה חדשה
בגיליון Google Sheets בדרייב.

**הגיליון:** [לידים - פרגולות, דקים, מעקות וגדרות](https://docs.google.com/spreadsheets/d/1X851yBAkmOK_9Ot2pQ87wOxbtfpTXI_LiTva4icnFJI/edit)
נמצא בתיקיית `Pergula` בדרייב.

הטופס אוסף **שם מלא, טלפון ויישוב/כתובת** (שלושתם חובה), ובנוסף סוג הפרויקט
והערות חופשיות.

---

## שני שלבי הפעלה

הדף כבר עולה ועובד, אבל עד שלב 2 הוא **לא שולח נתונים** — לחיצה על "שליחה"
מציגה את מסך האישור ואומרת שזו תצוגה בלבד.

### שלב 1 — ההגדרות

ב-[`page.body.html`](page.body.html), בתחתית הקובץ, יש בלוק `CONFIG` יחיד:

```js
var CONFIG = {
  endpoint:        "PASTE_YOUR_APPS_SCRIPT_URL_HERE",
  whatsapp:        "972559272777",
  whatsappDisplay: "055-927-2777"
};
```

מספר הוואטסאפ כבר מוגדר. `whatsapp` הוא בפורמט בינלאומי ללא `+` וללא
מקפים, ו-`whatsappDisplay` הוא אותו מספר כפי שהוא מוצג בדף.

### שלב 2 — חיבור הגיליון

1. פתחו את [הגיליון](https://docs.google.com/spreadsheets/d/1X851yBAkmOK_9Ot2pQ87wOxbtfpTXI_LiTva4icnFJI/edit)
   ובתפריט: **תוספים ← Apps Script**.
2. מחקו את מה שיש בעורך, והדביקו את כל התוכן של [`apps-script/Code.gs`](apps-script/Code.gs).
3. שמרו, ואז **Deploy ← New deployment**:
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**  ← קריטי. בלי זה גולשים אנונימיים לא יוכלו לשלוח.
4. אשרו את ההרשאות (מסך "Google hasn't verified this app" ← Advanced ← Go to…).
5. העתיקו את ה-**Web app URL**. הוא נראה כך:
   `https://script.google.com/macros/s/AKfy…/exec`
6. הדביקו אותו כ-`endpoint` ב-`CONFIG`, ואז הריצו `bash build.sh` ודחפו:

```bash
bash build.sh
git commit -am "חיבור הגיליון"
git push
```

לבדיקה: פתחו את כתובת ה-Web App בדפדפן. אם חוזר `{"ok":true,…}` — היא חיה.
אחר כך שלחו פנייה אחת מהדף ובדקו שהשורה הופיעה בגיליון.

## עלייה לאוויר על pergula.online

הקוד כבר ב-`main`, וקובץ `CNAME` בשורש מצהיר על הדומיין. נשארו שני
שלבים ידניים, **בסדר הזה**.

### א. DNS ב-Namecheap

Domain List ← Manage ← **Advanced DNS**.

קודם **מוחקים** את שתי רשומות החנייה שקיימות שם כברירת מחדל — הן
מתנגשות עם GitHub:

| למחוק | |
|---|---|
| `A Record` | `@` → `192.64.119.72` |
| `CNAME Record` | `www` → `parkingpage.namecheap.com` |

אם יש גם `URL Redirect Record` על `@` — למחוק גם אותו.

ואז מוסיפים חמש רשומות:

| Type | Host | Value | TTL |
|---|---|---|---|
| A Record | `@` | `185.199.108.153` | Automatic |
| A Record | `@` | `185.199.109.153` | Automatic |
| A Record | `@` | `185.199.110.153` | Automatic |
| A Record | `@` | `185.199.111.153` | Automatic |
| CNAME Record | `www` | `eranmx-spec.github.io.` | Automatic |

ארבע כתובות ה-A הן שרתי GitHub Pages, וארבעתן נחוצות. ה-CNAME של
`www` גורם ל-`www.pergula.online` להפנות לדומיין הראשי.

### ב. הפעלת Pages ב-GitHub

**Settings ← Pages ← Source: „Deploy from a branch" ← Branch: `main` / `(root)` ← Save**

בשדה Custom domain אמור להופיע `pergula.online` מעצמו, מתוך קובץ ה-CNAME.

אחרי ש-GitHub מסיים לאמת את הדומיין, מסמנים **Enforce HTTPS**. התיבה
הזו אפורה עד שהתעודה מונפקת — זה יכול לקחת עד שעה מרגע שה-DNS מתעדכן,
וזה תקין.

מכאן והלאה כל `git push` ל-`main` מתעדכן באתר אוטומטית.

> ניסיתי להפעיל את Pages דרך GitHub Actions, אבל ה-`GITHUB_TOKEN` של
> workflow לא יכול להפעיל Pages בריפו שבו הוא מעולם לא הופעל — ולכן
> הצעד הזה חייב להיעשות פעם אחת מהממשק.

## מבנה

| קובץ | תפקיד |
|---|---|
| `page.body.html` | **מקור האמת.** כאן עורכים תוכן, עיצוב ו-`CONFIG`. |
| `index.html` | נבנה אוטומטית מ-`page.body.html`. אל תערכו ידנית. |
| `build.sh` | עוטף את המקור ב-`<head>` עם מטא-תגיות ו-favicon. |
| `apps-script/Code.gs` | הקוד שרץ בצד Google וכותב לגיליון. |
| `img/` | שתים-עשרה התמונות שבדף. |
| `pic/` | הקולאז'ים המקוריים שהתקבלו. לא מוגש לגולשים. |
| `tools/crop-pics.ps1` | חתך את `pic/` ל-`img/`. הרצה חד-פעמית. |

אחרי כל עריכה של `page.body.html` צריך להריץ `bash build.sh` לפני commit.

## תקשורת: וואטסאפ בלבד

אין בדף אף קישור `tel:` ואף אפשרות חיוג — לפי בקשה. כל דרכי הפנייה
מובילות לוואטסאפ (`055-927-2777`), ויש סעיף שלם בדף שמסביר ללקוח למה
זו הדרך הנכונה: הידיים על מכונה, תמונה חוסכת עשר שאלות, הכל נשאר כתוב,
ואפשר לכתוב בשעה שנוחה.

שדה הטלפון בטופס נשאר, אבל מתויג **„מספר וואטסאפ"** — כי זה המספר שאליו
תחזרו בהודעה.

## תוכן שצריך לעבור עליו

הטקסטים נכתבו כדי להיות אמינים ומקצועיים, אבל **הם הנחות שלי, לא עובדות
שאומתו מולכם.** עברו על אלה ותקנו לפי המציאות שלכם:

- שם העסק **"עץ וצל"** — placeholder.
- אחריות **5 שנים על השלד** ו**שנתיים על הגימור**.
- זמני האספקה בשלבי התהליך (ייצור 2–4 שבועות, התקנה 1–3 ימים).
- **"ייצור בנגרייה עצמית"** ו**"מדידה ללא עלות"** — הצהרות שיווקיות מחייבות.
- כל המפרטים הטכניים (מידות שלבים, מרווחים, סוגי עוגנים, חומרים).

גובה מעקה 105 ס״מ ומרווח סורגים עד 10 ס״מ נלקחו מת״י 1142; ודאו מול היועץ
שלכם שזו הדרישה הרלוונטית לפרויקטים שאתם מבצעים בפועל.

### התמונות

התמונות ב-`img/` נחתכו מהקולאז'ים שהתקבלו, והן **לא צילומים של עבודות
שלכם**. לכן:

- הסעיף בדף נקרא **„סגנונות"** ולא „הפרויקטים שלנו", והכיתובים מתארים
  סגנון ולא פרויקט שבוצע. זה מכוון — אל תשנו את זה ל„עבודות שלנו"
  כל עוד אלה התמונות.
- ודאו שיש לכם זכויות שימוש בהן.
- ברגע שיש צילומים אמיתיים משלכם, החליפו את הקבצים ב-`img/` באותם
  שמות — הדף יתפוס אותם בלי שינוי קוד. אז גם אפשר לקרוא לסעיף
  „העבודות שלנו".

## מה הדף כן עושה

- RTL מלא, עברית, רספונסיבי ממסך רחב עד נייד.
- ערכת נושא בהירה וכהה לפי העדפת המערכת של הגולש.
- ולידציה בעברית: שם, מספר ישראלי (מקבל גם `+972` ומקפים), וכתובת.
- כפתור וואטסאפ צף, שהופך לסרגל תחתון בנייד.
- המספר נשמר בגיליון כטקסט, כך שה-0 המוביל לא נעלם.
- תצוגה מקדימה של קישור בוואטסאפ מראה את תמונת הפרגולה המקומרת.
